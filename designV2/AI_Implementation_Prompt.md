# TimeHub 桌面日历 · AI 实现指令（100% 还原设计稿）

> 用途：将本文件全文作为 Prompt 投喂给编码 AI（或作为开发任务的验收基准）。
> 唯一视觉基准：`designV2/mockup.html`（V2.0 高保真原型，单文件、0 外部依赖）
> 配套基准：`designV2/TimeHub_UI_Design_Spec_V2.md`（设计规格）+ `designV2/shots/s1–s9.png`（9 屏终图）

## 一、角色与总目标

你是 TimeHub 桌面日历软件的实现工程师。你的任务**不是重新设计，而是像素级复刻**设计稿。
设计稿（`designV2/mockup.html`）是唯一视觉真相（Single Source of Truth）。
任何视觉决策——颜色、字号、间距、圆角、阴影、图标、布局结构——以设计稿为准；
设计稿没有的，先提出方案并标注「设计稿未定义」，不得自行默默决定。

## 二、铁律（违反任意一条即视为不合格）

1. **禁止取色自由发挥**：所有颜色必须来自设计稿的 Design Token（`:root` / `html[data-theme="dark"]` 中的 CSS 变量）。代码中不允许出现任何未经 Token 化的硬编码色值。
2. **禁止改布局结构**：原型中的层级结构（侧边栏 / 主区 / 头部 / 内容区）必须一一对应实现，不得合并、省略或"优化"结构。
3. **禁止改动度量**：间距走 8px 栅格（4px 半步长允许），字号、圆角、阴影全部按 Token 表执行，不得"目测差不多"。
4. **禁止替换图标**：UI 中的图标以原型内联 SVG sprite 为准，逐一等价实现（Slint 中可用相同 path 数据或同构图标）。
5. **不得因"实现难度"降级设计**：如某效果（毛玻璃、阴影、动画过渡）在当前框架难以实现，必须上报并给出替代方案评估，由人决策，不得静默降级。
6. **偏差必须记录**：任何与设计稿不一致之处，写入《偏差清单》：位置 + 设计稿值 + 实现值 + 原因。

## 三、Token 映射（设计稿 → 实现）

将原型 `:root` 中的全部 CSS 变量提取为全局主题定义（Slint 建议放入 `ui/theme.slint` 的 `global Theme {}`），至少覆盖：

| Token 类别 | CSS 变量前缀 | 说明 |
|---|---|---|
| 颜色 | `--bg-*` `--text-*` `--accent*` `--c-*` | 亮/暗两套，按 `data-theme="dark"` 值对应实现暗色主题 |
| 字号 | 原型中 px 值 | 12/13/14/16/18/22/28 阶梯，建立 `font-*` 常量 |
| 圆角 | `--r-sm/md/lg` | 直接映射 |
| 阴影 | `--shadow-1/2/3` | 直接映射 |
| 间距 | 8px 栅格 | 建立 `space-1(4) space-2(8) space-3(12) space-4(16)...` 常量 |

**事件三色规则**（V2 核心修正，必须实现）：事件按日历类别着色 = 类别色 15% 透明度 tint 背景 + 同类别色边框 + 类别色深化 25% 的标题文字。tint 与深化色由 `COLOR_HEX` 基色计算（参照原型 JS 的 `fillBg()` / `shade()` 函数），运行时对用户自定义日历颜色同样适用该算法。

## 五、状态完整性

每个可交互组件必须覆盖全部状态，样式基准取原型中已有的 hover 逻辑（如 `.mcell:hover`、`.w-ev` hover 层级）：

- 默认 / hover / 按下 / 选中 / 焦点
- 禁用态（设计稿未定义 → 用 `--text-3` + 40% 透明度，记入偏差清单）
- 加载态、空态（参照 s9）
- 暗色主题下全部屏逐一过检（Token 换值，不得出现硬编码残留导致的"暗色漏白"）

## 六、验收标准（DoD）

1. **截图对比**：每屏在相同窗口尺寸（基准 1440×900 桌面窗）下截图，与 `designV2/shots/` 终图并排比对。
2. **像素容忍度**：元素位置偏差 ≤ 2px；颜色必须完全一致（取自 Token，非"看起来像"）。
3. **Token 覆盖率**：grep 代码中硬编码色值（`#RRGGBB` / `rgb(`），UI 层出现即为 0 个。
4. **双主题**：亮/暗主题切换后 9 屏全部正确，无对比度回退。
5. **无静默降级**：偏差清单为空，或每条都有明确原因与决策记录。
6. **交互可用**：视图切换（月/周/今天/待办）、新建日程对话框、主题切换可真实操作，行为与原型 JS 逻辑一致（如月网格周首对齐、"+N 更多"、当前时间线计算）。

## 七、推荐工作流

1. 通读 `designV2/mockup.html` 源码：提取 `:root` Token → 写 `theme.slint`（或等价主题层）。
2. 按原型 DOM 结构搭 UI 骨架（先结构后样式）。
3. 逐屏实现：每屏完成后截图自检，与终图比对。
4. 实现暗色主题与状态覆盖。
5. 输出《偏差清单》+ 9 屏实现截图，交人工终审。
