# 左侧导航性能整改（2026-09-07）

## 已修改

- 非日历页面不再通过导航回调调用 `refresh_all`。待办、便签保留由保存/删除回调维护的模型；工具、记录、排班、课程表仅刷新本模块。
- 年历、日期锚点变化和时间轴跨度变化仍刷新日历数据。补充“三日 → 待办 → 日”回归，防止跳过刷新后残留三天模型。
- 全量刷新中的多次卡片同步合并为一次，完成所有源模型更新后再提交给卡片。
- 黄历按公历日期缓存，每线程最多 32 条。缓存返回独立数据副本，跨日和不同选中日期不会串用。
- 本轮未修改 Slint 布局，遵循 Slint 模型复用要求保留既有交互；生成并查看工具页预览 `target/navigation-tools-preview.png`。

## 测量环境与边界

Windows，本机 960×640 软件渲染；测试构建（非 Release），独立 SQLite 数据库，100 条每日重复会议。使用真实 `AppWindow`、Rust 导航回调和桌面卡片数据源；没有操作真实用户数据。

| 待办 | 0.36 ms | 54.15 ms | 53.56 ms |
| 工具 | 1.10 ms | 128.31 ms | 48.30 ms |
| 记录 | 0.76 ms | 79.38 ms | 47.82 ms |
| 便签 | 0.27 ms | 69.42 ms | 47.21 ms |
| 课程表 | 0.58 ms | 82.68 ms | 52.71 ms |

上述为单次诊断样本，不是统计 p95，不包含 Windows 输入队列、GPU 合成和显示器呈现。强制全量刷新列也使用新黄历缓存，不能冒充旧版基线。实际桌面“点击到显示”尚未量化。

另行测量未缓存黄历计算：约 2205.7 ms（测试构建）；100 次缓存读取的平均值低于本次整微秒计时分辨率。缓存内容与未缓存结果完全一致，测试覆盖不同日期和返回副本的独立性。此数据不能直接当成 Release 的节省量。
